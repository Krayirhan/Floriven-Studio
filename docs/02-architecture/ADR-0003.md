## Bağlam

AI üretim adımları (brief normalizasyonu, ScreenGraph, DesignSpec üretimi, validasyon-düzeltme döngüsü) farklı gecikme profiline sahip; uzun süren, iptal edilebilir ve bağımsız ölçeklenebilir işlerdir. Core API'nin Java/Spring Boot kümesiyle aynı process içinde çalıştırılması seçeneklerden biridir; ancak Python ekosisteminin ML/AI kütüphane desteği avantajı göz ardı edilemez.

## Karar sürücüleri

- AI ekosistemi (Pydantic, LangChain/benzeri, model client SDK'lar) Python'da çok daha olgun
- Bağımsız ölçekleme: generation yükü artınca yalnızca worker kümesi büyütülür
- Core API'yi uzun LLM çağrısından izole etmek
- Pydantic ile çıktı validasyonu ve tip güvencesi
- Python içinde evaluation, guardrail ve prompt yönetimi araçlarına erişim

## Alternatifler

### A — Java içinde LLM çağrısı (Core API'de)

**Artılar:** Tek dil, tek deployment.  
**Eksiler:** Java LLM kütüphaneleri Python ekosistemi kadar olgun değil; bağımsız ölçekleme zorlaşır; uzun çağrılar thread pool'u bloke edebilir.

### B — Ayrı Python Worker + Message Queue (seçilen)

**Artılar:** Python AI ekosistemine tam erişim; bağımsız ölçekleme; Core API izolasyonu; async job modeli ile iptal/retry yönetimi.  
**Eksiler:** İki dil ve iki deployment birimi; ek servis iletişimi ve gözlemlenebilirlik altyapısı gerektirir.

### C — Managed AI API (harici orchestration servisi)

**Artılar:** Altyapı bakımı yok.  
**Eksiler:** Vendor lock-in; prompt ve validasyon mantığı üzerinde kontrol kaybı; fiyatlandırma öngörülemeyen biçimde değişebilir.

## Karar

**B — Ayrı Python Worker** seçildi. Core API job'u kuyruğa koyar ve sadece durum izler. Python worker'ı kuyruğu tüketir, LLM çağrısını yapar, Pydantic ile doğrular ve DesignSpec patch'i üretir. İletişim RabbitMQ (veya yönetilen eşdeğeri) üzerinden; job kimliği ve correlation ID her adımda taşınır.

## Sonuçlar

- **Olumlu:** AI ekosistemi özgürlüğü; bağımsız ölçekleme; Core API izolasyonu.
- **Olumsuz:** İki dil standardı, iki test/lint/CI pipeline, cross-service tracing kurulumu.
- **Sözleşme:** Worker ile API arası iletişim JSON şemasıyla sabitlenir; şema değişikliği iki tarafın birlikte yayımlanmasını gerektirir.
- **Geri alma:** Worker yük altında sorun yaratırsa aynı kuyruk üzerinde ek worker instance başlatılabilir; mimari değişiklik gerekmez.

## Doğrulama

Worker'ın ürettiği DesignSpec patch'i fixture testleriyle doğrulanır. Gecikme, hata oranı ve retry sayısı Prometheus/OpenTelemetry ile izlenir.
