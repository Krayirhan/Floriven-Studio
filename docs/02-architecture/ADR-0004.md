## Bağlam

Görsel editörün DesignSpec düğümlerini ekranda render etmesi gerekiyor. Seçenekler: HTML/DOM, SVG, Canvas 2D veya WebGL. Seçim; erişilebilirlik, metin kalitesi, drag-drop kolaylığı, performans ve export uyumluluğunu etkiliyor.

## Karar sürücüleri

- Erişilebilirlik (screen reader, klavye, ARIA) zorunludur
- Metin render kalitesi ve font sub-pixel hinting önemli (tasarım aracı)
- Drag-drop, selection box, resize handle gibi etkileşimler standard DOM event'larıyla yönetilebilmeli
- Canvas/WebGL çok sayıda öğede daha performanslı; DOM tek öğe manipülasyonunda daha esnek
- Figma export için SVG çıktısı üretilmeli (bu render teknolojisinden bağımsız)

## Alternatifler

### A — Canvas 2D / WebGL

**Artılar:** Çok sayıda öğede yüksek FPS; custom renderer kontrolü.  
**Eksiler:** Erişilebilirlik sıfırdan uygulanmalı; metin render tarayıcıya devredilemiyor; event sistemi yeniden kurulmalı; hata ayıklama zorlaşır.

### B — DOM/SVG-First (seçilen)

**Artılar:** Tarayıcı erişilebilirlik motoru kullanılır; standart CSS layout ve event'lar çalışır; geliştirici deneyimi daha kolay; metin platform kalitesinde.  
**Eksiler:** Binlerce düğümde performans DOM mutation maliyetiyle sınırlıdır; ancak MVP ölçeğinde bu sınıra ulaşılması beklenmez.

### C — Hibrit (DOM + Canvas overlay)

**Artılar:** İkisinin avantajını birleştirir.  
**Eksiler:** İki render katmanı senkronizasyonu karmaşık; hata yüzeyi genişler; MVP için erken optimizasyon.

## Karar

**B — DOM/SVG-First** seçildi. Editör bileşenleri React üzerinde DOM ile render edilir. SVG overlay seçim, kılavuz ve geometrik dekorasyon için kullanılabilir. Canvas katmanı yalnızca kanıtlanmış performans darboğazı sonrası ve yalnızca ilgili alt ağaç için eklenir. Export için ayrı SVG serializer DesignSpec'i doğrudan çevirir; render katmanından bağımsızdır.

## Sonuçlar

- **Olumlu:** Erişilebilirlik test edilebilir; standart tooling çalışır; hızlı geliştirme.
- **Olumsuz:** MVP sonrası yoğun proje ölçeğinde (500+ düğüm) performans revizyonu gerekebilir.
- **Eşik:** 60 FPS hedefinin sağlanamadığı proje boyutu belirlenmeli; o eşikte virtualization veya canvas patch değerlendirilir.
- **Erişilebilirlik:** Her interaktif düğüm `role`, `aria-label` ve klavye erişimini DOM katmanında taşır; Canvas geçişi bu gerekliliği kaldırmaz.

## Doğrulama

100 düğümlü proje senaryosunda Lighthouse performans skoru ≥ 85 hedeflenir. Erişilebilirlik testi axe-core ile CI'da otomatik çalışır.
