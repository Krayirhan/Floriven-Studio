## Bağlam

Floriven Studio birden fazla uygulama ve servis içerecek: web uygulaması (React/TS), Core API (Java/Spring Boot), AI Worker (Python/FastAPI) ve ileride export worker, CLI araçları gibi ek paketler. Bu bileşenlerin ayrı repo'larda mı yoksa tek monorepo içinde mi tutulacağı karar gerektirir.

## Karar sürücüleri

- `DesignSpec` JSON Schema gibi paylaşılan tip tanımlarının tek yerden yönetilmesi
- Frontend, backend ve AI worker arasında API sözleşme testlerinin kolay kurulması
- Atomic commit: birbiriyle ilişkili değişikliklerin tek PR'da taşınabilmesi
- Küçük başlangıç ekibinde bağlam geçişi maliyetinin düşük tutulması
- CI/CD pipeline'larının affected-only stratejisiyle optimize edilebilmesi

## Alternatifler

### A — Ayrı repo'lar (polyrepo)

**Artılar:** Her servis bağımsız sürümlenir; izin ve erişim granüler yönetilebilir.  
**Eksiler:** Paylaşılan tipler için ayrı paket ve publish akışı; cross-repo PR koordinasyonu; başlangıç ekibi için yüksek bağlam maliyeti.

### B — Monorepo, Turborepo ile (seçilen)

**Artılar:** Paylaşılan paketler (`@floriven/design-spec`, `@floriven/api-types`) workspace içinde yerel bağlantılı; affected-only build ve test; tek PR ile uçtan uca değişiklik; ortak lint/format/CI kuralları tek yerden.  
**Eksiler:** Repo boyutu büyüdükçe git operasyonları yavaşlayabilir; farklı diller (Java, Python) monorepo tooling'ine tam entegre olmaz.

### C — Monorepo, Nx ile

**Artılar:** Güçlü dependency graph ve task orchestration; plugin ekosistemi.  
**Eksiler:** Öğrenme eğrisi ve konfigürasyon ağırlığı Turborepo'ya kıyasla daha yüksek; başlangıç ekibi için fazla.

## Karar

**B — Turborepo tabanlı monorepo** seçildi. Java ve Python servisleri monorepo içinde klasör olarak yer alır; kendi araçlarıyla (Maven/Gradle, uv/pip) derlenir. Turborepo yalnızca JS/TS workspace'leri orchestrate eder; Java/Python build'leri kendi CI step'leriyle çalışır.

### Önerilen klasör yapısı

```
floriven-studio/            # monorepo kökü
├── apps/
│   ├── web/                # React + TypeScript web uygulaması
│   └── api/                # Spring Boot Core API (Maven/Gradle)
├── services/
│   └── ai-worker/          # Python FastAPI AI Worker (uv)
├── packages/
│   ├── design-spec/        # DesignSpec JSON Schema + TS tipleri
│   ├── api-types/          # OpenAPI'dan üretilen istemci tipleri
│   └── ui/                 # Paylaşılan React bileşen kütüphanesi (ileride)
├── turbo.json
├── package.json            # root workspace
└── pnpm-workspace.yaml
```

## Sonuçlar

- **Olumlu:** Paylaşılan `design-spec` paketi tek kaynak olur; frontend, backend ve AI worker aynı şemayı kullanır.
- **Olumlu:** `api-types` paketi OpenAPI spec'ten otomatik üretilir; manuel tip senkronizasyonu kalkar.
- **Olumsuz:** Java ve Python build'leri Turborepo'nun task graph'ına tam entegre olmaz; bu servisler için CI adımları ayrıca yazılır.
- **Bağımlılık:** pnpm workspace manager olarak seçilir (npm workspaces de çalışır, Turborepo her ikisini destekler).
- **Geri alma:** Ekip ve trafik kanıtlanınca bireysel servisler ayrı repo'ya çıkarılabilir; bu geçiş Turborepo kullanımından bağımsızdır.

## Doğrulama

İlk sprint sonunda `packages/design-spec`'in hem `apps/web` hem `services/ai-worker` tarafından tüketilebilir olduğu entegrasyon testiyle doğrulanır. Turborepo `--filter` ile affected-only pipeline çalışması CI loglarında kontrol edilir.
